# AGENTS.md

ferrolink is a Rust CLI that checks links, assets, and anchors in static HTML
builds, first of all Ardo documentation sites. The npm package `ferrolink`
wraps the same library for Node.js and Vite. Project language is US English.

## Layout

- `src/check.rs`: the pipeline (walk with ferralk, scan with rayon, check).
- `src/scan/`: two Ferroni regular expressions find tags and attributes
  (`ferroni.rs`); one collector decides what is a link or an anchor.
  `docs/parsers.md` records the comparison with the html5gum, html5ever, and
  lol_html tokenizers that chose it.
- `src/resolve.rs` and `src/site.rs`: browser URL resolution and static-host
  URL-to-file mapping.
- `src/deploy.rs`: `versions.json`, `_redirects`, and `vercel.json`.
- `tests/fixtures/site`: the end-to-end fixture `tests/cli.rs` checks.
- `node/`: the npm package, a pnpm project and a standards workspace.
  `native/` is the napi-rs binding crate, `src/` the TypeScript API
  (`index.ts`), loader (`native.ts`), and Vite plugin (`vite.ts`).
  `src/binding.d.ts` is generated by `pnpm build:native`; CI fails when it is
  stale. The tests in `test/` run against the built addon. The release builds
  one `@ferrolink/<platform>` package per napi target in `package.json`
  (`scripts/prepare-publish.ts`) and publishes through Trusted Publishing;
  `scripts/initial-publish.sh` set that up once per package. A new napi
  target needs that script run again before the next release.

## Checks

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-features --locked
```

In `node/`:

```bash
pnpm install
pnpm build        # the addon for this machine, then the TypeScript
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
```

Performance claims need a measurement on a real build (`--timings`, hyperfine
on `ferrolink check`); `docs/parsers.md` has the method.

Commits follow Conventional Commits without a scope.

# Standards-managed repo guardrails

- Do not hand-edit managed files or standards-owned marker sections.
- If `standards check` reports drift, run `standards apply` or update standards.
- The repository's own gate may omit `standards check`; CI can still fail on it.

Node repositories:

- Fix or format every file reported by `oxfmt` whenever practical.
- For generated files, prefer formatting in the generator step.
- If formatting is not viable, use repo-local `.prettierignore`.
- Never add repo-specific ignores to managed `.oxfmtrc.json`.

Rust repositories:

- Keep `cargo fmt --all --check` and
  `cargo clippy --workspace --all-targets --all-features -- -D warnings` green.
- Lint levels belong in `[workspace.lints]`, never in managed `rustfmt.toml`.
- `rust-version` in `Cargo.toml` is the only MSRV; every other mention is a
  derived copy.
- Record a cargo-deny finding as a narrow, commented exception in `deny.toml` —
  never by widening the org allow-list.
